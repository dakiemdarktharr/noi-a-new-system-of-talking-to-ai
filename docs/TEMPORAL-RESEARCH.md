# Temporal recognition: implementation and research decision

Reviewed 2026-11-05. This application trains a small **personal, isolated-sign classifier** from the user's labeled clips. The live screen applies that classifier to a rolling window. It does not contain pretrained Vietnamese sign-recognition weights. A vocabulary list is a labeling aid, not a trained recognition model. MediaPipe supplies hand landmarks, not the meaning of a sign.

## Decision

Use a compact temporal CNN over hand landmarks for local training and bounded inference cost. Keep the existing DTW matcher as a separately identified baseline for experiments with very few clips; do not mix a DTW match score into neural confidence or call template matching pretrained recognition. The current live integration uses the trained CNN. There is no defensible universally “best” architecture without the target language, capture setup, evaluation protocol and actual deployment timings.

| Method | Where it is useful | Main cost or limitation | Decision for this app |
| --- | --- | --- | --- |
| Multivariate DTW + nearest examples | A tiny personal vocabulary, a few demonstrations, immediate enrollment; variable execution speed | Comparison cost grows with templates and sequence length; distances require rejection thresholds; no learned signer invariance | Useful baseline, especially before enough neural-training data exists |
| Small temporal CNN | Bounded windows, parallel convolutions, directly available TensorFlow.js training and persistence | Fixed temporal resolution; learns the training distribution; windows must contain the relevant action | Implemented, about 52k parameters for two classes |
| GRU/LSTM | Compact recurrent state; streaming sequence models | Recurrent time dependence; browser performance must be measured; not automatically more accurate than CNNs | A valid future ablation, not a justified default replacement |
| ST-GCN / adaptive graph models | Joint connectivity, hands + body topology, larger skeleton datasets | Graph operations/export complexity; still depends on reliable joints and representative training data | Strong next-stage skeleton baseline after collecting a multi-signer dataset |
| Skeleton Transformer / Siformer | Long-range relationships, feature groups, missing-data methods | More parameters and data demands than this small local CNN; headline accuracies can use incompatible splits | Research candidate; evaluate under our own held-out signers before adoption |
| RGB + keypoint two-stream / S3D | Appearance plus hands, face and upper-body information; continuous recognition with sequence losses | Larger preprocessing/training/runtime budget; additional modalities and labels needed | Appropriate for a later server-trained, exported model, not local few-clip training |

These are engineering judgments informed by the primary sources below. They are not measured rankings on this application's dataset.

## What is actually implemented

`src/lib/features.ts` produces 32 timestamp-sampled steps of 172 bounded features. Each anatomical hand has its own slot and explicit presence mask. Its 83 features contain the local, palm-normalized 21-joint shape, a separate camera-frame 6D orientation basis (radial + forward axes), absolute image wrist position, displacement from its first observed wrist, velocity, finger curls, spread and image palm scale. Six shared channels retain both-hand presence, relative image wrist x/y, image-plane wrist distance, clip duration and temporal position.

The two orientation axes preserve global rotation after shape normalization; rotating the same finger configuration therefore remains distinguishable. Relative hand spacing uses wrists in the same aspect-corrected image coordinates. **Never subtract independently centered left/right MediaPipe world landmarks to infer inter-hand distance.** Image wrist distance is not a metric 3D distance. No body- or face-relative reference is available in this hand-only model. Fixed sampling can miss a very rapid transition, and initial-position subtraction alone cannot supply body location.

`src/lib/temporal.ts` trains Conv1D(24, kernel 5) → Conv1D(32, kernel 3) → average pooling(2) → Conv1D(48, kernel 3) → flatten → Dense(32) → dropout(0.15) → class softmax. Flattening retains coarse temporal order. This is a small **temporal CNN**, not a reproduction of the residual/dilated causal TCN from Bai et al. Two labels yield 52,330 parameters (about 205 KiB of float32 weights before container metadata). Every additional label adds 33 parameters. Default training is at most 48 epochs using Adam, with validation-loss early stopping and restoration of the best weights when a held-out set exists. TensorFlow.js chooses its available backend; CPU is a fallback. Training yields to the event loop between epochs, but this does not promise uninterrupted rendering on every device.

The API is `new TemporalClassifier()`, asynchronous `load()`, `train(samples, onProgress, options?)`, `predict(frames)`, synchronous `getSummary()` and `dispose()`. Models, labels, feature schema and support descriptors are saved together with TensorFlow.js's native `indexeddb://noi-temporal-v1` persistence. A failed persistence operation keeps the trained model usable in memory and returns `persisted: false`. Model and Adam slot tensors are released on disposal/replacement. Raw video is not a neural input here: the model trains on the landmarks recorded alongside each clip.

Predictions require sufficient visible-hand coverage, a current visible hand, softmax score at least 0.68, top-two margin at least 0.18, and proximity to the predicted class's training-feature support. `NO_SIGN` / `__no_sign__` wins are rejected. No-hand input is always rejected, so negative training examples should contain visible idle hands, transitions and ordinary non-sign hand motion. The support-distance gate and thresholds are conservative heuristics, **not a calibrated open-set recognition guarantee**. Softmax score is not empirical accuracy or the probability that a human interpretation is correct. The live view retains a gated prediction for 1.8 seconds so a sign that matches only one window remains readable.

## Data and evaluation

The minimum enforced by the API is two classes with three usable whole clips each. This permits an experiment, not a reliability claim. A practical starting collection target is **15–30 independently performed clips per label across at least three capture sessions**, including ordinary non-sign examples. That range is a collection recommendation, not a published sufficiency theorem. Start with a small, visually distinct vocabulary; use mistakes on held-out clips to decide which labels need more data. Do not record one long take and split it into many near-duplicate “independent” samples. Include natural speed, position and distance variation, but do not mirror or rotate signs indiscriminately: those transforms may change identity or meaning.

Training and validation contain disjoint whole clips. When a viable second session exists, the splitter holds an entire session out while retaining at least two training examples per class. The held-out session may cover only some labels; inspect counts and per-label coverage before interpreting its aggregate accuracy. If several sessions exist but none can be held out safely, no validation score is invented. With one session and at least five clips per class, the fallback holds out whole clips and explicitly reports `validationMode: 'clip'`; this measures neither unseen-session nor unseen-signer performance. With fewer clips it reports no validation accuracy. The held-out validation set guides early stopping, so it is not an untouched final test set.

The current sample schema records sessions, not signer identities. Consequently it cannot claim signer-independent evaluation. For that goal, add explicit consented signer IDs, group all sessions from the same signer into one partition, and retain a final unseen-signer test set. Include a separate unknown-sign/idle set, publish per-class recall and confusion matrices, report false acceptances per minute on continuous video, and measure p50/p95 end-to-end latency on the target device. Vocabulary size, negative prevalence, device, frame rate, crop/window policy and split protocol must accompany any accuracy or speed number.

Rolling-window classification of an isolated sign is not continuous sign-language recognition. Continuous recognition needs temporal segmentation/alignment, coarticulation, repeated-sign handling and sequence evaluation; translation additionally needs grammar and non-manual information. TwoStream-SLR uses sequence-level gloss supervision and CTC; attaching it to this hand-only interface would require new modalities, data and deployment work. Vietnamese, American, German, Chinese and Argentinian sign languages are not interchangeable class dictionaries.

## Primary evidence and source quality

1. [MediaPipe Hand Landmarker Web guide](https://ai.google.dev/edge/mediapipe/solutions/vision/hand_landmarker/web_js). **Quality:** official implementation documentation; explicitly describes normalized image coordinates, per-hand geometric-center world coordinates, handedness and synchronous browser inference. Supports keeping image-relative and hand-local geometry separate and moving expensive tracking off the UI thread when possible. It does not claim to recognize sign meaning.

2. [Carmona & Climent, A Performance Evaluation of HMM and DTW for Gesture Recognition (2012)](https://doi.org/10.1007/978-3-642-33275-3_29). **Quality:** original experiment comparing classifiers on its own Kinect gesture dataset, with sample-count and runtime discussion; limited scope. Supports retaining DTW as a low-data baseline and recognizing template-count-dependent runtime. Its small gesture benchmark does not establish accuracy for Vietnamese signing or this camera.

3. [Bai, Kolter & Koltun, An Empirical Evaluation of Generic Convolutional and Recurrent Networks for Sequence Modeling (2018)](https://arxiv.org/abs/1803.01271). **Quality:** original multi-task sequence-model comparison with [author code](https://github.com/locuslab/TCN); not a sign-language benchmark. Establishes temporal convolution as a serious alternative to canonical GRU/LSTM models, not proof that our CNN beats them for signing. Their residual, dilated, causal architecture differs from this implementation.

4. [Yan, Xiong & Lin, Spatial Temporal Graph Convolutional Networks for Skeleton-Based Action Recognition (AAAI 2018)](https://arxiv.org/abs/1801.07455). **Quality:** original graph-model paper evaluated on Kinetics and NTU-RGBD; full-body action recognition rather than a Vietnamese sign recognizer. Supports explicit spatial joint topology plus temporal edges as a principled next model family.

5. [Li et al., Word-level Deep Sign Language Recognition from Video: A New Large-scale Dataset and Methods Comparison (WACV 2020)](https://arxiv.org/abs/1910.11006). **Quality:** original WLASL dataset/methods paper with [author repository](https://github.com/dxli94/WLASL); directly studies isolated ASL and compares appearance/pose methods. Explains why hand orientation, subtle movement and larger vocabularies matter. Its language, labels and evaluation cannot be transferred to Vietnamese by renaming output classes.

6. [Pu, Lim & Chong, Siformer (ACM MM 2024; arXiv posting 2025)](https://arxiv.org/abs/2503.20436). **Quality:** original method with [author code](https://github.com/mpuu00001/Siformer), feature-isolated processing, missing-feature discussion and computational table. Table 3 reports a 2.55M-parameter configuration, 0.46G average FLOPs and 0.0324 seconds average inference under its setup; these are **not browser-device measurements**. Section 4.1 uses a random 80/20 LSA64 split and a custom eight-test-samples-per-class WLASL100 split. Therefore its headline 86.50% / 99.84% results do not establish unseen-signer Vietnamese performance and should not be directly ranked against results using official/different splits.

7. [Chen et al., Two-Stream Network for Sign Language Recognition and Translation (NeurIPS 2022)](https://arxiv.org/abs/2211.01367). **Quality:** original paper and [released code/models](https://github.com/FangyunWei/SLRT), inspected full-text method and experiments. Combines RGB with HRNet face, hand and upper-body keypoint heatmaps, CTC, auxiliary supervision and frame-level distillation. Experiments use Phoenix-2014, Phoenix-2014T and CSL-Daily; authors report training on eight V100 GPUs. Supports multimodal continuous-recognition research, not a ready-to-use hand-only Vietnamese browser model.

8. [TensorFlow.js saving/loading guide](https://www.tensorflow.org/js/guide/save_load) and [Layers API](https://js.tensorflow.org/api/latest/#layers.conv1d). **Quality:** official runtime documentation, checked against the installed library's TypeScript/source. Supports actual in-browser neural training and native IndexedDB model persistence. Device performance still requires measurement.

The broad 2024–2026 search also surfaced newer graph, few-shot and vision-language proposals. Search snippets alone did not justify adopting a model or repeating their benchmark claims. Few-shot transfer after large-scale pretraining must not be confused with training a random-initialized network from three personal clips.

## Verification performed

The unit suite executes actual TensorFlow.js CPU backpropagation and inference. Synthetic hand geometry checks fixed bounded feature dimensions, absent-hand masks, retained orientation, image-space inter-hand spacing, movement direction, duration and whole-session partitioning. A two-class synthetic orientation exercise checks decreasing training loss, prediction, `NO_SIGN` rejection, held-out synthetic clips and tensor cleanup. These are **software regressions only, not measurements of human sign-recognition accuracy**. No synthetic fixtures are inserted into the user's dataset or presented as webcam predictions. TypeScript compilation also passes.

No human-labeled Vietnamese recognition accuracy, signer-independent accuracy or end-to-end camera latency has been established by this work. The exact browser persistence/live integration checks are recorded by the parent integration task.
